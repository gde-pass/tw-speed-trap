# TW SpeedTrap — code audit, 2026-10-07

Scope: the Android app (`app/`) and the pure-JVM detection engine (`detection/`), at
v1.4.4 (`feb4cfb`). Four read-only passes (service + audio, Compose UI, data + update,
detection engine) plus Android lint, dependency versions and APK composition. The
highest-severity items were re-verified by hand against the source. The pipeline
(`pipeline/`) was only read where it defines the client/server update contract.

Severity: **S1** = wrong or missing alert, crash, or data loss in normal riding;
**S2** = real bug with a plausible trigger; **S3** = minor bug / robustness;
**S4** = polish or optional improvement.

Numbers quoted for the detection findings were checked against the shipped data
(2736 point cameras, 1109 with null bearing, 19 sections).

## S1 — fix first

### 1. Re-armed camera behind the rider re-fires when crossing 100 km/h
`detection/.../AlertEngine.kt:149-166`. `evaluate` never checks that a non-disarmed
camera is *ahead*; it only checks travel bearing vs enforced bearing and the ring.
With defaults (300 m / 500 m, re-arm 1.5×) the re-arm ring of a 300 m firing is 450 m,
*smaller* than the 500 m high-speed ring.
Scenario: brake under 100 km/h for an expressway camera (fires, ring 300), pass it,
accelerate past 100 km/h: at 460 m behind it re-arms, at 485 m behind it fires again
("camera 485 m") and the next fix chimes all-clear. This is the canonical expressway
pattern. Fix: gate firing on `isAhead(fix, camera)` when the bearing is trustworthy,
and compute the re-arm distance from `max(firedRing, highSpeedAlertDistanceM) × rearmFactor`.

### 2. False "average too high" at the legal limit on curved sections
`detection/.../AverageSpeedTracker.kt:199-211` (and the live projection at `:110-113`).
`remainingM` is the straight-line distance to the exit but the section is `lengthM` of
road, so the projection at entry is `speed × length / chord`. 壽卡: 6026 m road,
3535 m chord, limit 40 → a rider at exactly 40 km/h is projected at 68 km/h and warned
on the first in-section fix. 金門大橋: 60 km/h projects to 78. Fix: scale remaining by
`lengthM / chord(entry, exit)` and additionally require the *current* speed to exceed
the limit before warning.

### 3. Low-speed bearing fail-open alerts opposite-direction cameras at red lights
`detection/.../AlertEngine.kt:196-198`: below 15 km/h `bearingMatches` is true for any
camera. 244 cameras have an opposite-direction twin within 100 m, 404 within 300 m,
mostly red-light cameras at signalised junctions where riders stop. Scenario: queued
50 m before a junction whose camera enforces the other direction → "red-light camera
50 m", then an all-clear chime after the green. Fix: add the 120 s bearing memory that
`AverageSpeedTracker.effectiveBearing` (`:337-342`) already has, and fail open only
when no recent bearing exists.

### 4. Overlay bubble can be orphaned for the life of the process
`app/.../service/BubbleOverlayController.kt:53-62`. The single `combine(...).collect`
has no `catch`; `SupervisorJob` isolates nothing because it is the only child. Any
throwable from the DataStore flow (corrupt prefs file) or from `apply()`
(`updateViewLayout` at `OverlayBubble.kt:176/360` throws once the system has pulled the
window, e.g. overlay permission revoked while an alert card is up) kills the collector.
An attached bubble then can never be detached and the settings toggle does nothing:
exactly the "bubble pins the process at oom_adj 200" invariant in CLAUDE.md.
Fix: `runCatching` around `apply()` with detach-on-failure, relaunch the collector on
failure, `.catch { emit(emptyPreferences()) }` on `SettingsRepository.settings`, guard
`updateViewLayout` like `removeView`.

### 5. A corrupt or truncated local `cameras.db` is permanently unrecoverable
`app/.../data/CameraRepository.kt:20-29` copies the asset straight to the final path
(no tmp, no fsync, no rename); `openReadOnly()` (`:84-85`) has no fallback;
`DbUpdater.kt:66` calls `repository.metadata()` *before* downloading, so a broken file
throws there and the updater can never repair it. `DbUpdater.kt:77-82` writes the
downloaded db with `writeBytes` then `renameTo` without `fsync`, so a power loss within
seconds of an update can leave a zero-length file. Result: every detection start fails
with "stopped because of an error" until the user clears app data.
Fix: tmp + `fd.sync()` + rename for both copies; in `openReadOnly()` catch
`SQLiteException` → delete and recopy from assets; treat a failing `metadata()` as
"no local version" in the updater.

### 6. On a zh-TW phone with language "system", a Mandarin voice reads English text
`app/.../util/LocaleOverride.kt:27-35` + `DetectionService.runDetection`. `resolve`
returns the device locale (zh-TW) for the TTS voice, while strings resolve to the
English default (there is no `values-zh-rTW`). `setLanguage(zh-TW)` succeeds so the
voice-missing warning never fires. The primary market gets unintelligible alerts.
Fix: pick the TTS locale from the locale that actually matched a resource bundle
(`configuration.locales.getFirstMatch(arrayOf("en", "fr")) ?: Locale.ENGLISH`), or
ship `values-zh-rTW`.

### 7. Fine location is requested without coarse location (verify on a 12+ device)
`app/.../ui/MainScreen.kt:67-68, 129`. Android 12+ documents that an
`ACCESS_FINE_LOCATION` request made without `ACCESS_COARSE_LOCATION` in the same call
is ignored (no dialog; logcat "must be requested with ACCESS_COARSE_LOCATION"). If that
holds on the target devices, a fresh install can never enable the Start button. The
emulator workflow `pm grant`s location, so this path has not been exercised.
Fix: `RequestMultiplePermissions()` with both, then upgrade if only coarse was granted.
Also (`:124-153`) there is no handling of permanent denial: after two denials the
cards' buttons do nothing. Add an "Open app settings" fallback when
`shouldShowRequestPermissionRationale` is false.

## S2 — real bugs, fix soon

### Detection
8. **No accuracy gate before firing** (`AlertEngine.kt:148-166`; `LocationSource.kt:38-40`
   maps no-speed to 0 and no-accuracy to 99 m). Network fixes in tunnels and urban
   canyons carry no speed/bearing and 100–2000 m accuracy: speed 0 skips the bearing
   filter, so any camera within 300 m of the reported point fires, and the resulting
   pending pass cannot resolve (accuracy > 50) until GPS returns. Fix: `accuracyM >
   FIRE_ACCURACY_GATE_M → return null`; derive speed from displacement when
   `hasSpeed()` is false.
9. **Hairpin before the camera → premature all-clear and no re-alert**
   (`AlertEngine.kt:182-190`). "Behind" is judged from the instantaneous heading; at a
   hairpin apex a camera 100–300 m ahead by road sits abeam → all-clear chime, bubble
   green, camera stays disarmed and is passed silently. Fix: for cameras with a
   bearing, decide "passed" from the camera's own axis as `passedExit` does for
   sections (`AverageSpeedTracker.kt:165-179`); for null-bearing cameras require
   behind on two consecutive fixes plus increasing distance.
10. **Exit timing slop under-reports short tunnel sections after GPS loss**
    (`AverageSpeedTracker.kt:145-146`). After a gap the first fix can be 60 m past the
    gantry while entry was 60 m before: 辛亥 (487 m) at a true 60 km/h is announced as
    49 km/h with no over-limit. Fix: on an exit following a gap, add the along-track
    projection of (fix − exit) to `travelledM`, as the estimated path already does.
11. **Crawl-entry backdating can rewind up to 10 minutes**
    (`AverageSpeedTracker.kt:298-300, 325`). A 10 min stop at a shared portal (壽卡 is a
    rest stop) backdates the entry by the stop → a true 60 km/h reads 22 km/h. Fix: cap
    backdating (≤ 30 s) or backdate to the along-track sign change.
12. **Pass detection ignores 51–99 m accuracy** (`AlertEngine.kt:130` gate 50 vs 100 in
    the tracker and stationary detector). The active alert persists 1.5 km past the
    camera and the all-clear chime comes 90 s late. Align to 100 m.
13. **GPS loss after the first fix is invisible** (`LocationSource.kt:30-45` has no
    `onLocationAvailability`; `BubbleOverlayController.kt:140` shows NoGps only before
    the first fix). In a tunnel the bubble stays green and the notification freezes on
    the last speed. Fix: emit availability, and a 5–10 s no-fix watchdog → `gpsStale`.
14. **`requestLocationUpdates` failure is never observed** (`LocationSource.kt:46`). On
    a device without Play Services the service says "running" forever with no fixes.
    Add `addOnFailureListener { close(it) }`.

### Data / update
15. **Validation does not exercise the queries the app runs; no rollback**
    (`DbUpdater.kt:116-137`, `CameraRepository.kt:34-39, 52-53`). A db with the same
    schema version but a renamed column or NULL `city` passes, is installed, then
    reports UpToDate forever while every detection start fails. Fix: run the real
    `loadCameras()/loadSections()` against the tmp file as the validation step; keep
    `cameras.db.prev` and roll back on load failure.
16. **Bundled db never replaces an existing local file** (`CameraRepository.kt:22`).
    Users with auto-update off keep install-day data through every app update; when
    `SUPPORTED_SCHEMA_VERSION` bumps, the upgraded app opens an old-schema file. Fix:
    compare the asset's `data_version`/`schema_version` with the local meta at
    `ensureDatabase()` and replace when newer or different.
17. **SHA-256 is integrity, not authentication** (`UpdateVerifier.kt:26-30`). The
    manifest and db are published by the same `GITHUB_TOKEN`; anything that can write
    the `data` release (compromised pinned action, leaked token) reaches every install
    within 7 days. Fix: Ed25519 signature over `manifest.json`, public key in the app,
    private key in a GitHub environment secret used only by `data-update.yml`.
18. **Server-side bad data is retried with full re-downloads** (`DbUpdater.kt:60-81`,
    `UpdateWorker.kt:25`). Checksum mismatch / failed validation → `retry()` → up to
    ~5 downloads a day until the next good publish. Mark these permanent or remember the
    rejected `sha256`.
19. **Manual check and worker race on the same `cameras.db.tmp`** (`SettingsScreen.kt:206`,
    `UpdateWorker.kt:20`, `DbUpdater.kt:75-76`). Fix: process-wide `Mutex` and a
    per-attempt temp file.
20. **Cameras and sections loaded in two separate opens** (`CameraRepository.kt:31-32,
    63-64`). A swap between them mixes data generations for the whole ride. Load both
    in one `db.use {}`.
21. **DataStore has no corruption handler; blocking read on the main thread**
    (`SettingsRepository.kt:15`, `MainActivity.kt:25`, `TwSpeedTrapApp.kt:20`,
    `DetectionService.kt:120`). A corrupt prefs file is a launch crash loop. Add
    `ReplaceFileCorruptionHandler { emptyPreferences() }`; mirror `languageTag` into
    SharedPreferences for `attachBaseContext`.

### Service
22. **Bluetooth auto-start reacts to every ACL connection** (`BluetoothAutoStartReceiver.kt:37`),
    with auto-stop off by default: earbuds connecting at home start a 1 Hz
    high-accuracy GPS service for hours. Fix: let the user pick the device
    (`EXTRA_DEVICE` address) or use the headset/A2DP profile broadcasts; suggest
    auto-stop when auto-start is on.
23. **Receiver component is always enabled** (`AndroidManifest.xml:49-55`): every BT
    connect cold-starts the process (Application.onCreate, DataStore, WorkManager) even
    with the setting off. Toggle it with `setComponentEnabledSetting`.
24. **Tap-to-start and failure notifications are silent no-ops when POST_NOTIFICATIONS
    is denied** (`TapToStart.kt:44`, `DetectionService.kt:185`). Check
    `areNotificationsEnabled()` and warn from the auto-start toggle.
25. **Uncaught exception in the receiver's bare coroutine scope crashes the process**
    (`BluetoothAutoStartReceiver.kt:49-59`, same pattern in `TwSpeedTrapApp.kt:19-22`).
    Add a `CoroutineExceptionHandler`.
26. **TTS init completing after `release()`** (`Announcer.kt:91-135`) sets
    `voiceMissing = true` on an idle screen and drives a shut-down engine. Add a
    `released` flag.
27. **Fixed 3 s delay truncates the auto-stop / failure announcement**
    (`DetectionService.kt:144-146, 195-197`). The French sentence is ~4 s; a cold
    engine says nothing. Wait for the ledger to drain (≤ 8 s) instead.

### UI
28. **Unguarded `startActivity` on implicit intents** (`SettingsScreen.kt:235, 240, 339,
    349`; `MainScreen.kt:90-98`; `AboutScreen.kt:96, 110`). `ACTION_INSTALL_TTS_DATA`
    is shown exactly when no TTS engine exists, which is when it does not resolve →
    `ActivityNotFoundException` crash. One `startActivitySafely` helper with a
    Snackbar fallback.
29. **Status-bar icons invisible in system light mode** (`MainActivity.kt:38`,
    `Theme.kt:28-29`). `enableEdgeToEdge()` defaults pick dark icons on the forced dark
    background. Pass `SystemBarStyle.dark(TRANSPARENT)` for both bars.
30. **Map screen ignores insets** (`MapScreen.kt:122-147`): back FAB under the status
    bar, legend under the nav bar. `windowInsetsPadding(WindowInsets.safeDrawing)`.
31. **Sliders write DataStore on every drag frame** (`SettingsScreen.kt:131-148,
    373-385`): dozens of file rewrites per second and a lagging thumb. Local state +
    persist in `onValueChangeFinished`.
32. **Main screen never shows `activeAlert`, `activeSection` or `voiceMissing`**
    (`MainScreen.kt:241-275` vs `DetectionStatus.kt:31-36`). A fired alert looks like
    the normal "camera in 300 m" line; a rider with no voice installed gets silent
    alerts with no hint on the main screen. Add a red/amber banner, the projected
    section average, and the voice warning with its install button.
33. **"GPS off — no alerts!" is 14 sp in a corner and the row can overflow in French**
    (`MainScreen.kt:199-214`). `weight(1f)` + promote to a full-width error banner.
34. **"Check for update now" runs in `rememberCoroutineScope`** (`SettingsScreen.kt:76,
    197-221`): rotation discards the result and leaves the version line stale. Move to a
    ViewModel / application scope.
35. **Attribution list is out of date** (`strings.xml:110`, `values-fr:108`): datasets
    100856, 178168, 172174, 159972, 178144, 178121 are ingested but not credited; the
    Open Government Data License requires it. Generate it from the db `meta` table or a
    non-translatable string array.

## S4 — optional improvements

- Time-based alert ring: `max(alertDistanceM, speed × 15 s)` clamped ≤ 600 m removes the
  99→100 km/h step and keeps ≥ 15 s of lead time.
- Along-track projection on gantry bearings as the single crossing-time mechanism
  (fixes #10 and #11 together).
- Time-based secondary re-arm (all-clear + 120 s) for urban detours.
- Throttle GPS after ~2 min stationary and restore on movement.
- Speak "Detection stopped" when stopped from bubble/notification; require a long-press
  to stop while an alert card is up.
- Keep screen on while detection runs and the main screen is in front; bigger glance
  typography (speed ≥ 96 sp).
- My-location overlay and a load-failure message on the map.
- Per-schema manifests (`manifest-v{N}.json`), ETag on the manifest fetch, persisted
  "last checked" in Settings, `setInitialDelay(1, DAYS)` on the periodic work.
- ViewModels for Settings and Map; a `Typography` in the theme.
- Repo: the weekly binary db commit adds ~26 MB/year to `.git`; fetch it from the
  `data` release at build time or use git-lfs.

## Verified OK (do not re-investigate)

  `startForegroundService` wrapped; degrade-to-notification correct; `stopSelf()` in
  the failed path cancels the 5 s FGS timeout. No exact alarms, no wake locks.

- Bluetooth receiver `exported=true` is required and safe (protected broadcast);
  `RECEIVER_NOT_EXPORTED` for `PROVIDERS_CHANGED_ACTION` is correct.

## Second pass (2026-10-07, v1.5.2)

Trigger: the rider passes Taichung cameras without an alert. Two read-only agents
(detection, app) plus a manual data.gov.tw catalog sweep; every item below was
re-verified in code before acting.

Data (the main cause — the cameras were not in the database):
- **#71 S1 fixed** — the dataset watch's keywords missed 科學儀器執法 / 違規照相 /
  區間平均速率 titles. Taichung's own fixed list **83881** (224 rows, 118 new: the national
  set has none of the city's red-light cameras) was never seen. Integrated with 彰化 27969,
  新竹縣 109336/173211, 臺東 178734; keywords widened; 26 ids recorded in the baseline.
- **#72 S1 fixed** — `parse_bearing` stored 「X往Y」 as Y. Correct for straight movements,
  wrong for turn movements (西往北): 81 Kaohsiung cameras alerted cross traffic instead of
  the rider they photograph. Now the opposite of X.
- **#73 S2 fixed** — the same device geocoded up to ~120 m apart by two agencies (21 of 224
  83881 rows vs 7320) survived the 45 m cross-source dedupe as a double alert. Same-type
  rows that both carry an agreeing bearing merge up to 120 m.
- **#74 S3 fixed** — one resource URL holding several CRLF-joined files (178734) and rows
  listing two devices as "lon, lat" per column were unparseable.

Detection:
- **#75 S2 fixed** — 45° heading tolerance against 4-direction source data: a camera on a
  road skewed 45° from its cardinal tag flickered or never matched. Default 60°; cross
  traffic (90°) still rejected. Test: diagonal road.
- **#76 S2 fixed** — a fired camera left behind in one jump (tunnel, GPS gap beyond the
  index coverage) stayed disarmed for the rest of the ride. `sweepDisarmed` re-arms by
  distance on every fix. Test: tunnel then return.
- **#77 S3 open** — a fix gap longer than ring/speed (≈13 s at 90 km/h) jumps the ring;
  nothing useful can be said once the camera is behind. Accepted.
- **#78 S3 fixed (v1.5.5)** — `AverageSpeedTracker.checkPreAlerts` announces "zone ahead,
  limit N" at the point-camera ring (speed band, hysteresis, trusted fix, direction known,
  gantry upstream along its axis); the entry still speaks at the gantry. 3 tests.
- **#79 S4 open** — phones without `hasSpeed()` keep the 300 m ring at highway speed.

App:
- **#80 S2 fixed** — TTS engine death mid-ride (voice app updated, killed for memory)
  left every later `speak` returning ERROR with nothing recovering. A rejected utterance
  now rebuilds the engine, re-queues the alert and shows the voice warning; the bind-wait
  queue keeps every alert instead of the last one; `awaitIdle` returns at once when the
  engine never bound.
